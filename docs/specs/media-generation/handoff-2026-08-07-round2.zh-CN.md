## 三、一处根因、三个症状（本轮最值得记的一条）

agent 生成的图落在 `%APPDATA%\...\1one\` 而不是会话工作目录，而项目面板明写着「生成的图片和视频就保存在该目录」。

排下去发现落点错**只是第一个症状**。会话页是**按 workspace 匹配媒体结果卡片**的（`MessageList` 的注释本就写着「agent 起的任务只带 workspace」），所以落错地方的 job 连带丢掉：

- 缩略图（DOM 实测 0 张）
- 打开所在目录 / 重新生成 / 引用到输入框
- 花费那一行

**修一处，三个症状全解。** 根因链三段缺一不可：

1. `StdioTransport::spawn`（aionrs 的 `aion-mcp`）**不设 `current_dir`** → MCP 子进程继承 aioncore 的 cwd
2. 工具调用里**没有任何会话标识** → 主进程也无从解析
3. 于是薄壳只能落到 `process.cwd()` 或应用 workDir

解法是在 `FactoryContext` 那一层注入——那是唯一同时知道「哪个会话」和「MCP 配置」的地方。新增 `aionui-mcp/media_workspace.rs`，**刻意只给媒体这一个 server**：把工作目录发给所有会话 MCP，等于告诉任意用户配置的进程用户文件在哪。

## 四、我自己写出又抓回来的一个死代码修复

「已安装专家拿不到新人设」的判据第一版写的是 `local == previous`（逐字节相等 = 从没被改过）。逻辑看着完全正确，测试全绿。

真机数据一对就露馅：

|            | 行尾   | 长度 |
| ---------- | ------ | ---- |
| 目录（DB） | `\r\n` | 2192 |
| 安装到磁盘 | `\n`   | 2137 |

差值 55 正好是换行数——内容一致，是写入路径归一成了 LF。所以 `local == previous` **永远为假** → 每个安装都被判成「用户改过」→ **整个刷新是死代码，且没有任何测试会红**。

抓到它靠的不是读代码，是**去比对两份真实数据**。与前一轮 §9.9 第三层（curl 看 `mcp_server_ids` 全 `null`）是同一个方法。

## 五、还剩什么（按优先级，每条都带前提）

### 1. ⚠️ 网页端媒体根本加载不了（最靠前，其余两条依赖它）

```ts
export const buildMediaUrl = (absolutePath: string): string =>
  `one-media://local/?path=${encodeURIComponent(absolutePath)}`;
```

`one-media://` 是 **Electron 主进程注册的自定义协议**，浏览器里不存在，而这个函数**没有任何浏览器分支**。所以 WebUI 里 `<img src="one-media://...">` 是坏图，生成的图和视频全部加载失败。

**前提**：得先有一条 **HTTP 取文件路由**（现在只有 `/api/fs/image-base64`，对视频不适用，且设计规则 D6 是「媒体字节永不过消息通道，只传路径」）。

⚠️ **安全面**：这条路由会读本地路径返回文件字节，是新增攻击面。上一轮结束时的计划是**限制在媒体 job 已登记的资产路径内**（照 job store 校验），而不是接受任意 path。动手前先跟用户确认这个约束。

### 2. 远程模式下「打开所在目录」开的是服务器目录

`MediaResultActions` 的 `showItemInFolder` 走 `httpPost('/api/shell/show-item-in-folder')`，在**后端那台机器**上开目录。本机 WebUI 无碍，企业远程模式下点它会去开服务器的目录。

**用户已拍板**：改成**下载 / 浏览器打开**（不是隐藏）。

**判据**（与用户讨论后定的）：

```
远程 = isEnterpriseRemoteActive() || (isWebUiBrowserMode() && hostname 非环回)
```

两个谓词都已存在于 `httpBridge.ts`，只需再加一个环回判断。

⚠️ 这是个**保守启发式**，有意识地接受一处误伤：用户用本机 LAN IP 访问自己的机器时，功能本可以用却会被关掉。原因是浏览器端拿不到「访问者是不是就坐在这台机器前」——`location.hostname` 只说明他敲了什么地址。要分辨得看请求的 remote address 是否环回，那是服务端信息。用户认可这个取舍。

### 3. 支持一次生成多张独立图片

**⚠️ 我一度判断错，前提已更正。** 我原本说 `maxN: 1` 是模型真实上限，**这是错的**——用户截图证实豆包控制台上 Doubao-Seedream-5.0-pro 的「生成数量」是 **1–9**。

所以真相是 `catalog/imageModels.ts` 的 `ark-seedream` 条目**低报了模型能力**。第一步应是**核实各模型真实上限并改对目录**（seedream → 9），改完 `n=4` 大概率直接可用，未必需要做扇出。

仍需确认：ark 原生与 litellm 网关是否都支持 `n>1`、多资产在卡片里怎么展示、成本按张数计。只有当某模型确实 `maxN=1` 又要多张时，才需要 job 层扇出 `ceil(n/maxN)` 次调用（并发上限、部分失败语义另议）。

**别与「一张图内多格」混淆**——后者靠提示词已经能做到，本轮实测出过一张 2×2 的四格连环画。

### 4. 需要用户拍板：`X-Title` 该不该改

本轮把 `ClientFactory` 的 `X-Title: 'AionUi'` / `HTTP-Referer: 'https://aionui.com'` 改成了 `One Work` / `work.1oneclaw.com`（提交 `b377afbcf`）。

这两个 header 会显示在 OpenRouter 类网关**自己的应用榜单**上。我按「展示名」处理改了，但它严格说介于「品牌文案」与「外部标识符」之间——如果应当像 `appId` 一样钉死历史值（例如已有归属统计），这一处需要回退。**已向用户提出，未得到答复。**

## 七、网页端与桌面端的关系（本轮更正过一次）

`packages/web-host` **没有自己的 renderer**，网页端跑的就是同一份渲染产物。所以渲染层改动在架构上是共用的。

但 **`out/renderer` 停在 07-31**，比今天的改动旧一周。不出问题是因为 07-30 加的 dev 反代还在（`index.ts:810` 与 `webuiConfig.ts:239` 两个调用点都传了 `rendererDevServerUrl`），dev 下网页端实时反代到 vite；打包时 `out/renderer` 会重建。

⚠️ **但「代码共用」不等于「能力共用」**。我一度据此说「网页端天然同步」，那个结论**不完整**——`one-media://` 就是反例：同一份代码，在浏览器里那条链从来没通过。凡是碰到自定义协议、Electron API、本机文件路径的地方都会分叉。判断网页端是否可用，不能只看代码是否共用。

## 八、不要重犯的几条（承接前一轮 §10 的十九条，编号续）

20. **给测试命令接管道过滤，会同时截断结果和吞掉退出码。** 第一次跑 Rust 全量时接了 `grep | head -20`，回来正好 20 行且全是 `ok`，看上去全绿；完整重跑才露出 1 条失败（`CARGO_EXIT=101`）。`exit code` 拿到的是 `head` 的，不是 cargo 的。

21. **平台特有的比较，行尾会让它永远为假。** §4 那条。写「本地副本有没有被改过」这类判据时，先去对两份真实数据的字节数。

22. **一处根因可以长成三个互不相似的症状。** 落点错 / 卡片消失 / 花费消失，看起来是三个缺陷，其实是同一个 workspace 没传下去。**在修第二个之前，先问它和第一个是不是同一个原因**。

23. **「机制存在」不等于「链路连通」。** 参数裁剪告知的机制早就写好了，断在薄壳 `renderJob` 从 assets 重建文本那一行。**验证一个机制时，要一路查到最终消费方真的收到了。**

24. **agent 会为矛盾编一个解释，然后当成事实报告给用户。** 它明明察觉到「要 4 张只回 1 张」，仍然对用户说「4 张已生成完成」。**凡是工具没说清的，agent 会自己补——所以工具必须说清它没做到什么。**

25. **不要替模型的能力下结论。** 我断言 `maxN: 1` 是模型真实上限，用户一张控制台截图就推翻了（实为 1–9），真相是我们的目录低报了能力。**产品能力问用户或查官方控制台，别从自己的配置文件反推。**
