## 二、被用户推翻并已重做的一条架构（重要，别改回去）

**用户原话**：「不要搞模型闸门的白名单，后面的视频和图片模型会越来越多，不能每次都让开发者去放行吧」。

他是对的。原来的目录里混着**两种性质完全不同**的东西，必须分开看：

|                                             | 是不是白名单                                                           | 处置                                       |
| ------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------ |
| **按模型名匹配**（正则 / 名单）             | **是**。`gpt-image-2` 能用只因为把正则放宽到整个系列，新模型必须改代码 | **已废除**，改为用户在模型设置里打类型标签 |
| **Form C 的 `IMPLEMENTED_ENDPOINT_STYLES`** | **不是**。它管的是"有没有写过能说这个协议的代码"                       | **保留，删不掉**。没有驱动就真的调不通     |

现在的解析优先级（`catalog/resolve.ts::resolveMediaModelSpec`）：

1. **用户声明**（`provider.model_settings[model].model_kind`）—— 声明成别的类型直接返回 null（这就是"名字带 image 但我拿它当聊天模型"能从图片选择器消失的原因）
2. 内置目录条目
3. 用户声明但目录不认识 → 合成 spec：**图片默认 Form A**（OpenAI images 接口是兼容网关上的事实标准）；**视频不猜**，必须用户在同一处选 `media_endpoint`，否则不予提供

> ⚠️ 第 3 条里"视频不猜"是刻意的。各家异步任务接口互不兼容，猜错**只会在调用那一刻才失败**，那正是这层架构存在的理由。改这里之前想清楚。

用户 catalog JSON 覆盖（`catalog/overrides.ts`）仍在，但**退居高级出口**（改参数/改 API 形态），不再是"我网关上新增了个图片模型"的常规答案。

## 三、⚠️ 视频跑不通的真正原因——我今天推翻了先前结论

**旧结论（错的，别再照它排查）**：「应用配的 key 对视频没权限，换用户测试台那把 `sk-e9…` 就行」。这是 08-05 那条会话写进进展文档的，我今天也复述过一次。

**用户指出**：视频的 key 和其他模型是**同一把**，根本没有第二把 key 可换。

**实测推翻**（无效 token，零计费）：

```bash
# 同一把无效 token，同一个网关
POST /v1/chat/completions            -> 401 {"error":{"type":"authentication_error"}}   # 会鉴权
POST /v1/contents/generations/tasks  -> 200, body 0 bytes                                # 不鉴权
POST /v1/videos                      -> 200, body 0 bytes
POST /v1/this/path/does/not/exist    -> 200, body 0 bytes                                # 决定性
```

**最后一行是判据**：一个根本不存在的路径也返回 200 空 body。所以 `litellm-internal.123u.com` **对 `/v1/*` 下未配置的路径一律吞掉**，返回 200 空。

**真正的结论**：这个网关**根本没有代理 Ark 的任务 API**，和 key 的权限无关，换任何 key 都不会好。用户测试台能拿到 `cgt-…`，说明那边打的不是这个网关。

**接续者要做的**：视频 provider 指向**火山方舟直连** `https://ark.cn-beijing.volces.com/api/v3` + 一把 Ark key，而不是走这个 LiteLLM 网关。代码侧已就绪（`arkDriver` 对原生 `/api/v3` 根是 no-op，有测试钉死）。

> 顺带：正因为网关吞掉一切，`readJsonOrThrow` 的"2xx 空 body"分支（`e13287455`）就是用户唯一能看到的线索，那条错误文案值得保留。

## 五、这一天修掉的真缺陷（都是真机打出来的，不是静态审出来的）

1. **ark 驱动在兼容网关上缺版本段**：`/contents/generations/tasks` → nginx **405**，`/v1/...` → 200。ark-task 是唯一驱动视频的驱动，故经网关视频此前 100% 必挂。修法=版本段归一化提为共享 `adapters/baseUrl.ts`。
2. **`readJsonOrThrow` 对 2xx 空 body 抛裸 `SyntaxError`**：报错是 `Unexpected end of JSON input`，既不点名端点也不说原因。
3. **`tools.videoGenerationModel` 只有读没有写**：引擎按它取模型，但全仓没有任何地方写入 —— 视频在设置层面就是死的。
4. **用量上报只挂在 TCP 那条路上**：我加的渲染层直连路径会**静默逃过企业用量统计**。已搬到引擎级订阅 + `reportedJobs` 去重。
5. **生成图片的缩略图从来没显示过**（用户截图1）：走的是 markdown 那条 `/api/fs/image-base64`，而该端点对生成媒体的路径直接 **400**（带不带 workspace 都一样）。已改走 `one-media://`，真机确认两张图 1254×1254 真实解码。
6. **视频工具缺 `negative_prompt`**：目录声明了 `negativePrompt: true` 但工具 schema 没这个参数，等于声明了却送不进去。
7. **集成测试 teardown 的 ENOTEMPTY flake**：4 条测试全过但套件判失败，污染全量结果。

## 六、验证方法与踩过的坑（接续者会用到）

### 6.1 `bun run dev` 不重建主进程 bundle

**改主进程/common 代码后必须重启 dev**。本轮有一次真机跑，ark 修复（dev 启动前改的）生效而 `readJsonOrThrow` 修复（启动后改的）没生效——**同一次运行里一个在一个不在**，是这个坑最干净的证据。

### 6.2 CDP 连接方式

`chrome-devtools` MCP 连的是独立浏览器，**看不到 Electron 窗口**。要用裸 WebSocket 连 9230：脚本见本轮用的 `cdp.js` 套路（`/json/list` 找 `type:'page' && url含5173` 的 target → `Runtime.evaluate`）。

**取应用自己的模块**：`import('/@fs/D:/aionui-m0/1oneUI/packages/desktop/src/common/index.ts')` —— 直接 `import('/src/common/index.ts')` 会 404（Vite 根不是那里）。这是本轮打通渲染层验证的关键一招。

**⚠️ 渲染层走的是 WS 传输，不是裸 Electron IPC**：监听 `window.electronAPI.on('office-ai-bridge-adapter')` 收不到**任何** bridge 事件。本轮一度据此误判"IPC 广播没生效"，判据是**那个通道上其他事件也一条没有**。要验 IPC 就用上面那招拿到真实 `ipcBridge`。

**⚠️ Arco 下拉用合成 `click` 打不开**：必须发完整 `pointerdown/mousedown/pointerup/mouseup/click` 序列（用 `PointerEvent`）。第一次测出"菜单项 0 个"差点当成 bug。

**⚠️ 页签状态不跟 URL 走**：`activeTab` 是 `useState` 初始化的，只改 hash query 不会切页签，必须真去点或整页 reload；且"点页签 + 读内容"要放在**同一次求值**里。

### 6.3 零计费的真实端点探测

判断"路径对不对"不需要真 key：代理/路由错误在**鉴权之前**就以 404/405 暴露，路径正确则走到 401。本轮用它抓到了 ark 的 405，也用它证实了三个新驱动的提交路径正确（OpenAI/智谱/Kling 全部 401）。

⚠️ 但**这个网关是例外**（见 §3）：它对未配置路径返回 200 空，所以"200"在这里**不等于路径正确**。

### 6.4 后端重编

`powershell -NoProfile -File D:/aionui-m0/scripts/backend-rebuild.ps1`。
⚠️ **必须先关 dev app**，否则内嵌步骤报 `EPERM`（bundled 目录被占用）。本轮踩过一次：rebuild 在前、kill 在后，白等 10 分钟。

## 八、不要重犯的几条

- **别把类型标签改成按名字猜** —— 那是刚废除的白名单换地方复活。
- **别放开 `IMPLEMENTED_ENDPOINT_STYLES`** —— 它不是策略闸门，是"有没有驱动"。有测试（`catalogResolve.test.ts` 的 `still refuses an endpoint style that has no driver`）钉死。
- **别让媒体字节过 IPC/TCP** —— D6 铁律，2026-04-14 base64 事故在案。生成媒体一律走 `one-media://`。
- **precheck 刻意 fail-open** —— 拒绝必须意味着"策略说不行"而不是"请求没送到"。改成 fail-closed 会在端点抖动时把所有个人用户的媒体生成一起打死。
- **新增媒体入口必须走 `startMediaJob()`** —— 校验、企业 precheck、目录刷新都在里面；用量上报挂在引擎级订阅上。绕过它就等于绕过企业管控。
